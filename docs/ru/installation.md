# Установка

*English: [docs/installation.md](../installation.md).*

От нуля до работающего сервера CS2 и админ-панели в Yandex Cloud. Рассчитывайте на **около 20 минут вашего времени** плюс первую загрузку игры (около 60 ГБ, идёт сама).

> Хотите просто посмотреть панель? `npm run demo` запускает настоящую панель на имитации игрового сервера: <http://127.0.0.1:8080>. Аккаунт в облаке не нужен.

## 1. Что понадобится

| Что | Примечания |
|---|---|
| Аккаунт **Yandex Cloud** с платёжным аккаунтом | <https://console.yandex.cloud/> |
| **Каталог** под проект | Лучше отдельный: удаление каталога удалит всё. Запишите `folder_id` и `cloud_id` |
| **Аккаунт Steam** | Для токена игрового сервера (раздел 3). Если включите скины, лучше запасной аккаунт |
| Ваш **SteamID64** | 17 цифр, начинается с `7656119`. Узнать: <https://steamid.io> |
| Консоль с `yc`, OpenTofu или Terraform (>= 1.6), `python3`, `node` (>= 18), `npm` | В **[Yandex Cloud Shell](https://shell.yandex.cloud/)** всё есть. С ноутбука тоже можно: поставьте [yc CLI](https://yandex.cloud/ru/docs/cli/quickstart) и выполните `yc init` |

Стоимость зависит от текущего прайса Yandex Cloud, посмотрите его перед стартом. Устройство счёта такое: **игровая ВМ оплачивается только пока включена** (диск 100 ГБ платный всегда), **ВМ панели маленькая и всегда включена**, в Object Storage лежат бэкапы. Панель сама выключает игровую ВМ после 30 минут без игроков.

## 2. Развёртывание

```bash
git clone https://github.com/sink3x/cs2-server-admin-panel.git
cd cs2-server-admin-panel

cp terraform/terraform.tfvars.example terraform/terraform.tfvars
$EDITOR terraform/terraform.tfvars        # cloud_id, folder_id, ваш SteamID64 в cs2_admins

scripts/deploy.sh
```

Единственный файл, который нужно править, это `terraform.tfvars`:

```hcl
cloud_id  = "b1g..."           # yc resource-manager cloud list
folder_id = "b1g..."           # yc resource-manager folder list

cs2_admins = [
  { name = "you", steamid = "76561198000000000" },
]
```

Что делает `scripts/deploy.sh`:

1. собирает фронтенд и упаковывает приложение в `build/bundle.tgz` (`scripts/pack.sh`);
2. создаёт `terraform/secrets.auto.tfvars` (случайные токен агента, пароли RCON и БД, логины панели; права 0600, в git не попадает) и **один раз печатает первые логины панели**;
3. выполняет `init`, `validate` и двухэтапный `apply` (сначала ключ хранилища, потом всё остальное). Спрашивает подтверждение; флаг `--yes` его отключает;
4. печатает результат: `panel_url`, `game_ip`, `connect`.

Для OpenTofu: `TF=tofu scripts/deploy.sh`.

**Запишите напечатанные логины.** Они же лежат в `terraform/secrets.auto.tfvars`. Сохраните этот файл в надёжном месте: в нём все секреты развёртывания.

### Первая загрузка

Обе ВМ настраиваются сами. Панель доступна через одну-две минуты (Caddy получает сертификат Let's Encrypt для `<ip-через-дефисы>.sslip.io` или для вашего `panel_domain`). Затем игровая ВМ скачивает CS2 через SteamCMD, это занимает **10-30 минут**. Прогресс виден на странице «Обзор».

## 3. Токен игрового сервера Steam (GSLT)

Без токена сервер работает, но обычным способом из интернета к нему не подключиться.

1. Откройте <https://steamcommunity.com/dev/managegameservers> и создайте токен для **App ID `730`** (заметка любая).
2. Скопируйте его и выполните `scripts/set-gslt.sh`. Скрипт читает буфер обмена, проверяет формат, записывает токен в `secrets.auto.tfvars`, применяет и перезапускает игровую ВМ. Токен нигде не печатается.

Можно и до первого деплоя: `GSLT=<токен> scripts/init-secrets.sh`.

## 4. Открыть панель и зайти в игру

1. Откройте `panel_url` из вывода деплоя и войдите под напечатанным админским логином. **Смените пароль** на странице аккаунта.
2. Нажмите **Запустить**. Панель включит ВМ; при первом запуске ещё и установит игру.
3. В CS2 откройте консоль и выполните `connect <game_ip>:27015` (в выводе деплоя строка `connect` содержит готовую команду).

Друзей добавляйте в разделе **Пользователи**. У игроков ограниченная роль: они видят статус и, если вы разрешите в настройках, могут запустить сервер.

## 5. Дополнительно

| Что нужно | Как сделать |
|---|---|
| Свой домен для панели | `panel_domain = "panel.example.com"` и A-запись на `panel_ip`. Примените заново |
| Ограничить доступ к панели | `panel_allowed_cidrs = ["203.0.113.7/32"]` |
| SSH | `ssh_public_key = "ssh-ed25519 AAAA..."`, затем `scripts/ssh.sh` |
| ВМ помощнее | `cs2_cores = 4`. Диск данных отдельный, ничего не потеряется |
| Карты Workshop | `scripts/set-steam-web-key.sh` с [ключом Steam Web API](https://steamcommunity.com/dev/apikey) |
| Поиск по FACEIT | `PANEL_URL=https://... scripts/set-faceit-key.sh` |

Все переменные описаны в [configuration.md](../configuration.md) (на английском).

## 6. Обновление

Подтяните новую версию и задеплойте снова:

```bash
git pull
scripts/deploy.sh
```

- **ВМ панели** обновляет Terraform (новый бандл в метаданных), она перезапускается.
- **Игровая ВМ** берёт новый бандл **при следующей загрузке**. Идущая игра деплоем не прерывается. Остановите и запустите ВМ из панели, когда вам удобно.
- Сама игра обновляется через SteamCMD при каждом запуске сервера.

Перед крупными обновлениями читайте [CHANGELOG](../../CHANGELOG.md).

### По желанию: непрерывный деплой из GitHub Actions

Для вашего форка. Пока вы не включите, workflow ничего не делает.

1. Создайте бакет Object Storage под состояние Terraform и сервисный аккаунт со статическим ключом. Задайте `TF_STATE_BUCKET` и ключ в окружении `production` (точный список секретов и переменных в `.github/workflows/deploy.yml`).
2. Добавьте секреты и переменные в **окружение `production`** вашего форка.
3. Задайте переменную репозитория `DEPLOY_ENABLED=true`.

Деплой запускается после зелёного CI на `main` и только для пушей в этот же репозиторий, никогда не из pull request. Держите репозиторий **приватным или с ревью**: кто может менять `main`, тот может деплоить в ваше облако.

## 7. Бэкапы и восстановление

- Бэкап делается **каждую ночь и при каждом выключении**; в Object Storage хранятся последние 14. В нём `state.json`, конфиги плагинов и дамп базы.
- Страница «Бэкапы» в панели восстанавливает любой из них.
- Если диск данных оказался пустым (новый диск), игровая ВМ при запуске сама восстановит свежий бэкап.
- `terraform/secrets.auto.tfvars` и состояние Terraform храните сами, в бэкапы они не входят.

## 8. Если что-то не так

| Симптом | Что проверить |
|---|---|
| `deploy.sh` падает с ошибкой аутентификации | `yc init` (или истёк сеанс Cloud Shell), запустите заново |
| Панель открывается с предупреждением о сертификате | Подождите 2 минуты после первой загрузки. Let's Encrypt должен достучаться до портов 80/443 (`panel_allowed_cidrs` обязан это разрешать) |
| Сервер запущен, но друзья не заходят | Задан ли GSLT? ВМ в статусе `RUNNING`? UDP 27015 открывает Terraform. Проверьте `connect <ip>:27015` снаружи |
| В «Обзоре» агент недоступен | Игровая ВМ выключена или ещё грузится; агент слушает 8081 только для панели |
| Карта Workshop не грузится | Нужен ключ Steam Web API: `scripts/set-steam-web-key.sh` |
| После перезапуска пропали плагины | Ошибки установки видны в «Плагины»; лог агента `journalctl -u cs2-agent` (нужен SSH) |
| Кончилось место | Увеличьте `cs2_data_disk_gb` и примените; файловую систему расширьте как на любом диске Ubuntu |

Больше в [FAQ](../faq.md).

## 9. Удалить всё

Диск данных защищён `prevent_destroy`, а бакет не удаляется с содержимым, поэтому случайный `destroy` сервер не уничтожит. Чтобы удалить стек намеренно:

1. Скачайте нужные бэкапы из бакета.
2. Очистите бакет (консоль или `yc storage`).
3. Уберите строку `prevent_destroy` в `terraform/compute.tf` и выполните `tofu destroy`.

Или просто удалите каталог в консоли Yandex Cloud: вместе с ним удалятся все ресурсы.
