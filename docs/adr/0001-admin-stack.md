# ADR-0001: Технологический стек админ-панели

**Статус:** Proposed (предложено; миграция поэтапная, текущая панель остаётся рабочей)
**Дата:** 2026-11-07
**Решающий:** владелец проекта (alice)

## Контекст
Панель — тонкий слой: HTTP API + проксирование в агент на игровой ВМ (RCON, MySQL скинов, файлы) и в Yandex Cloud API; плюс SPA на ~250 КБ JS.
Нагрузка: единицы пользователей, десятки запросов в минуту. Узкое место — не CPU, а скорость разработки, читаемость и количество багов в UI.

Что есть сейчас: Node без зависимостей, vanilla-JS (`h()` собирает DOM руками), 75 тестов `node:test`, i18n через подмену русских строк в DOM, деплой бандлом в metadata ВМ (лимит ≈250000 Б после base64, сейчас ≈150 КБ tgz).

Боли: нет типов (ошибки ловятся в рантайме), ручная перерисовка (`renderPage`/`replaceChildren`), i18n по ключу-русской-фразе хрупок (шаблонные строки `${}` не переводятся), 600+ строк без перевода, страницы по 600–800 строк без компонентов.
Ограничения: один разработчик; ВМ малая (админ-ВМ всегда включена, дёшево); бандл ограничен лимитом metadata.

## Решение
1. **Бэкенд остаётся на Node.js, но на TypeScript** (сначала `// @ts-check` + JSDoc, затем `.ts`). Без фреймворка; максимум — `hono`/`fastify` позже, если понадобится валидация схем.
2. **Фронтенд: Preact + TypeScript + Vite** (signals для состояния, JSX/htm), страницы мигрируют по одной (strangler); `h()`-страницы живут рядом до полной замены.
3. **i18n: ключевые каталоги JSON** (`ru.json`, `en.json`, `de.json`, `fr.json`) + типобезопасный `t('key', params)`; ICU-плюрализация для чисел. Текущий словарь «русская фраза → перевод» конвертируется скриптом в каталоги.
4. **Доставка:** собранный `dist/` кладётся в Object Storage (он уже используется для бэкапов) и подтягивается ВМ при старте; в metadata остаётся только маленький загрузчик. Это снимает лимит 250 КБ.
5. **Тесты:** `node:test` для бэкенда (как есть) + Vitest для UI-логики + Playwright-смоук (логин, «Сервер», «Скины») в CI.

## Рассмотренные варианты
| Вариант | Скорость работы | Простота разработки | Размер бандла | Риск миграции | Вердикт |
|---|---|---|---|---|---|
| **A. Node+TS + Preact+TS+Vite** | отлично (I/O-прокси) | высокая: одна язык-пара, компоненты, типы | ≈15–25 КБ gz рантайм | низкий, постепенно | **выбран** |
| B. Node+TS + React+TS | отлично | высокая, больше экосистема | ≈45 КБ gz только React | низкий | избыточно тяжёлый, выгод для одного разработчика нет |
| C. Node+TS + Svelte 5 | отлично | очень высокая, мало шаблонного кода | самый маленький | средний: другой синтаксис, меньше готовых библиотек | достойная альтернатива, если Preact не зайдёт |
| D. Go (API) + Preact | отлично, один бинарник | средняя: два языка, дубли типов | бинарник 10+ МБ — не влезает в metadata | высокий: переписать 100% бэкенда и 75 тестов | выгоды нет: CPU не узкое место |
| E. Rust (axum) | максимум, но лишний | низкая: долгая компиляция, высокий порог | большой бинарник | очень высокий | избыточно для панели из 5 пользователей |
| F. Python FastAPI | нормально | средняя | зависимости, venv | высокий | теряем общий язык с фронтом; тот же Node быстрее на таком I/O |
| G. Оставить как есть | хорошо | падает с ростом | малый | нулевой | копится долг: без типов и компонентов каждая фича дороже |

## Анализ компромиссов
- **Почему не переписывать бэкенд.** Он 99% времени ждёт RCON/MySQL/YC API. Go и Rust ускорят то, что не тормозит, и заставят переписывать работающую авторизацию, Steam OpenID, Faceit, скины и тесты. Выигрыш — доли миллисекунд, цена — недели.
- **Почему Preact, а не React.** Тот же JSX и экосистема (`preact/compat`), но 3–4 КБ вместо ≈45 КБ; бандл критичен из-за лимита доставки. Svelte — равноценная альтернатива, но Preact проще мигрировать: текущий код уже «функция → DOM».
- **Почему TS на бэкенде тоже.** Один язык, общие типы API между сервером и UI (`/api/overview`, `glance`, скины) — главный источник багов сейчас (поля, которые «ожидались» на другой стороне).
- **Почему i18n-каталоги.** Нынешний подход переводит только точное совпадение строки; динамические (`${n} мин`) пропадают. Ключи + параметры исправляют это раз и навсегда, а CI-проверка «нет непереведённых ключей» не даёт регрессировать.
- **Скорость интерфейса.** Реальные выигрыши: код-сплиттинг по страницам, ленивая загрузка картинок скинов, кэширование каталога (сервис-воркер уже есть), виртуализация длинных списков скинов.
- **Красота.** Остаётся ваша дизайн-система на CSS-переменных; добавить токены (цвет/радиус/отступы) и набор базовых компонентов (Card, Stat, Pill, Table, Dialog), чтобы страницы собирались единообразно.

## Последствия
- Становится проще: рефакторинг и новые фичи (типы подсказывают), общие компоненты, предсказуемая перерисовка, полноценный i18n и проверка покрытия.
- Становится сложнее: появляется шаг сборки (Vite) и `package.json` с зависимостями — нужна лок-файл-дисциплина и обновления. Mitigation: ≤10 прямых зависимостей, сборка только в CI/на Mac, на ВМ — готовый `dist/`.
- Пересмотреть через 3 месяца: если Preact-миграция затянется — остановиться на гибриде; если число пользователей вырастет на порядок — вынести API на Fastify/Hono с валидацией схем.
